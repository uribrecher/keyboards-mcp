# Changesets Adoption (#137) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adopt [Changesets](https://github.com/changesets/changesets) so `keyboards-mcp` (published) and `sounds-and-recreation-app` (private) version + changelog independently from machine-readable changeset files — `changeset version` produces correct per-package bumps + changelogs, and `changeset publish` publishes only `keyboards-mcp` and skips the private app.

**Architecture:** A root-level `.changeset/` (config + README) drives the flow for both workspaces. The `@changesets/changelog-github` generator writes PR/author-linked entries. The app is versioned-but-never-published via `"private": true` (publish skip) + `privatePackages: { version: true, tag: false }` (version, no tag). Coupling is the existing `"keyboards-mcp": "^2"` dependency: a keyboards-mcp patch/minor stays in range and does **not** force-bump the app. This is a **pure-infra** change — no version bump and no changeset file ship in this PR; the mis-filed `[Unreleased]` app-rename entry is relocated from keyboards-mcp's changelog into a new app changelog.

**Tech Stack:** npm workspaces (Node 20+/22), `@changesets/cli@^2.31`, `@changesets/changelog-github@^0.7`, `@changesets/config@3.1.x` schema. Signed commits via SSH/1Password.

**Design spec:** `docs/superpowers/specs/2026-06-16-changesets-adoption-design.md`

## Pre-flight (read once before Task 1)

- **Branch / worktree:** Work happens on branch `worktree-changesets-137` (already created off `origin/main`). All commits stay on this branch — never push to `main`. The spec is already committed here (`docs/superpowers/specs/2026-06-16-changesets-adoption-design.md`).
- **Commits are signed.** The repo signs via SSH/1Password. In a sandboxed runner, signing silently no-ops — run every `git commit` with the sandbox disabled and verify with `git cat-file commit HEAD | grep -c gpgsig` (expect `1`). If signing fails because 1Password is locked, stop and ask the user to unlock — do **not** bypass signing.
- **`npm install`, not `npm ci`.** This PR changes `package.json` (root devDeps) so the lockfile must regenerate — use `npm install` at the repo root. This worktree currently has **no `node_modules`**, so the first install is a full workspace install (expected, may take a minute).
- **Changelog generator needs a token.** `changeset version` invokes `@changesets/changelog-github`, which calls the GitHub API. Locally, prefix the command with `GITHUB_TOKEN=$(gh auth token)`. (Confirmed available in this environment.) CI supplies this automatically — that's #138's concern, out of scope here.
- **Scope guard:** Do **not** touch `.github/workflows/release.yml` (that's #138). Do **not** commit any changeset file or any version bump — the only committed deliverables are the config, the README, the root `package.json` edits, and the two changelog files.
- **Current versions (don't bump them):** `keyboards-mcp` `2.0.0`, `sounds-and-recreation-app` `0.1.0`.
- **Verification verbs used below:**
  - `npx changeset status`
  - `GITHUB_TOKEN=$(gh auth token) npx changeset version`
  - `npm publish --dry-run -w keyboards-mcp` / `-w sounds-and-recreation-app`
  - `npm run lint` / `npm run test:check` (root delegators)
  - `git restore <paths>` + `git status --short` to undo throwaway verification

## [2.0.0] - 2026-06-14

First release published to npm. (Earlier `1.x` development was never published.)

### Added
- Global install with a `keyboards-mcp` CLI: run with no arguments to start the MCP
  stdio server, plus `install`, `uninstall`, `doctor`, and `broker` subcommands.

  doctor` reports broker status; `keyboards-mcp uninstall` removes the daemon.

  stored token) with build provenance.
- CI `audit` job that fails the build on high/critical advisories in production
  dependencies.

- The broker is no longer a manual prerequisite: `connect_to_keyboard` works against
  the already-running daemon. Connection and `mcb-unreachable` guidance now points at
  `keyboards-mcp doctor`.
- Leaner published package — the Electron Mock Runner and its heavy dependencies
  (Electron, peaks.js, konva, waveform-data) are excluded from the tarball, so an
  install pulls only the runtime dependencies.

### Removed
- The consumer-facing `postinstall` hook, which would fail on a global install.

[2.0.0]: https://www.npmjs.com/package/keyboards-mcp/v/2.0.0
